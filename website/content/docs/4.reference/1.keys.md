title: Keys
description: Every key in the spec-tacular TUI, screen by screen, taken from its key handlers.
---

The same action has the same key on every screen. Where you type, a bare letter is text, so the action takes ctrl instead: :key-cap{k="r"} becomes :key-cap{k="ctrl+r"}. Press :key-cap{k="?"} on the overview or in a review to see the keys in the TUI itself.

| Key | Action |
| --- | --- |
| :key-cap{k="a"} | Accept: a requirement, a risk, a document or a revision |
| :key-cap{k="r"} | Revise with AI: say what should change. :key-cap{k="ctrl+r"} where you type |
| :key-cap{k="x"} | Reject a requirement or risk, saying why |
| :key-cap{k="d"} | Defer a requirement or risk until it can be verified |
| :key-cap{k="ctrl+e"} | Open it in `$EDITOR`. :key-cap{k="E"} also works where nothing is typed |
| :key-cap{k="y"} | Copy it |
| :key-cap{k="q"} | Back. :key-cap{k="ctrl+c"} and :key-cap{k="esc"} also go back |

::note
A lone :key-cap{k="esc"} is unreliable: many terminals cannot deliver it until the next key arrives. :key-cap{k="ctrl+c"} always works as back or cancel, and quits only from the start screen and the overview.
::

## Everywhere

These keys work on every screen.

| Key | Action |
| --- | --- |
| :key-cap{k="ctrl+b"} | Open or close the AI usage details: driver, model, cost, per job |
| drag, then :key-cap{k="ctrl+c"} | Copy the text selected with the mouse. Without a selection, :key-cap{k="ctrl+c"} is back |
| :key-cap{k="ctrl+v"} | Paste the clipboard into the text you are typing |
| :key-cap{k="ctrl+shift+v"}, middle click | The terminal's own paste: several lines at once, and no line counts as enter |

Any key other than :key-cap{k="ctrl+c"} ends a mouse selection, so a later :key-cap{k="ctrl+c"} means back again. While the usage details are open, :key-cap{k="q"} or :key-cap{k="ctrl+c"} closes them.

## Start screen

The start screen shows the next setup step as buttons.

| Key | Action |
| --- | --- |
| :key-cap{k="←"} :key-cap{k="→"} :key-cap{k="↑"} :key-cap{k="↓"}, :key-cap{k="tab"} | Move between the buttons. :key-cap{k="shift+tab"} moves back |
| :key-cap{k="enter"}, :key-cap{k="space"} | Press the highlighted button |
| :key-cap{k="q"}, :key-cap{k="ctrl+c"} | Quit |

## Overview

The overview lists the changes and, after them, the roadmap slices that have no change yet. The selected change shows its next step as buttons.

| Key | Action |
| --- | --- |
| :key-cap{k="↑"} :key-cap{k="↓"}, :key-cap{k="k"} :key-cap{k="j"} | Select a change or a slice. A click works too |
| :key-cap{k="←"} :key-cap{k="→"}, :key-cap{k="tab"} | Choose between the next-step buttons |
| :key-cap{k="enter"} | Press the highlighted button: the next step |
| :key-cap{k="n"} | Start a new change |
| :key-cap{k="b"} | Report a defect: start a defect change |
| :key-cap{k="w"} | Let an agent draft the next artifact in the background. When the next step is implementing, open your agent on it |
| :key-cap{k="ctrl+e"}, :key-cap{k="E"}, :key-cap{k="e"} | Write the next artifact yourself, in `$EDITOR` |
| :key-cap{k="v"} | Read the latest written artifact. For the specs, this opens the review |
| :key-cap{k="s"} | Specify the next roadmap slice, once this change is specified. On a selected slice: start that slice |
| :key-cap{k="o"} | Reopen the report of a draft that stopped |
| :key-cap{k="A"} | Archive the selected change: shows what archiving would do, or why not yet |
| :key-cap{k="M"} | Regenerate the change's test matrices and their tests |
| :key-cap{k="f"} | Open the ground rules |
| :key-cap{k="h"} | Go to the start screen |
| :key-cap{k="ctrl+j"} | Open the jobs pane |
| :key-cap{k="?"} | Show help. Any key closes it |
| :key-cap{k="q"}, :key-cap{k="ctrl+c"} | Quit |

### Archive confirmation

After :key-cap{k="A"}, a box shows what archiving would do, or why it may not happen yet.

| Key | Action |
| --- | --- |
| :key-cap{k="enter"}, :key-cap{k="A"} | Archive it |
| :key-cap{k="q"}, :key-cap{k="ctrl+c"}, :key-cap{k="esc"} | Close without archiving |

### New change prompt

:key-cap{k="n"} and :key-cap{k="b"} ask for a description first, then a name proposed from it.

| Key | Action |
| --- | --- |
| :key-cap{k="enter"} | Next: name it. On the name: create the change |
| :key-cap{k="tab"} | Cycle through the proposed names |
| :key-cap{k="ctrl+u"} | Clear the line |
| :key-cap{k="ctrl+c"} | Cancel |

## Review

The review shows one item at a time: requirements, risks, design decisions, questions from formal forms and harness bindings.

| Key | Action |
| --- | --- |
| :key-cap{k="a"} | Accept the item |
| :key-cap{k="x"} | Reject it. Asks why; the reason may be empty |
| :key-cap{k="d"} | Defer it. Asks what would verify it; a reason is required |
| :key-cap{k="r"}, :key-cap{k="ctrl+r"}, :key-cap{k="e"} | Revise it with AI. On a question: give your own answer, and its requirement is revised with it |
| :key-cap{k="ctrl+e"}, :key-cap{k="E"} | Open it in `$EDITOR` at its line |
| :key-cap{k="y"} | Copy it |
| :key-cap{k="s"} | Skip it for now |
| :key-cap{k="n"}, :key-cap{k="j"}, :key-cap{k="↓"} | Next item |
| :key-cap{k="p"}, :key-cap{k="k"}, :key-cap{k="↑"} | Previous item |
| :key-cap{k="p"} on a global design decision | Promote it to a project-wide ADR |
| :key-cap{k="m"}, then a number | Mark a flagged value as an example rather than a contract. Any other key cancels |
| :key-cap{k="f"} | Show all specificity flags, when more than three are folded |
| :key-cap{k="t"} | Show or fold the test matrices under a formal form |
| :key-cap{k="g"} | Open the glossary in `$EDITOR`, on an item with a formal form |
| :key-cap{k="pgdn"}, :key-cap{k="space"} / :key-cap{k="pgup"} | Scroll a card taller than the screen. The mouse wheel works too |
| :key-cap{k="?"} | Show the review's keys. Any key closes them |
| :key-cap{k="q"}, :key-cap{k="ctrl+c"} | Back to the overview |

In the reject or defer prompt, :key-cap{k="enter"} confirms and :key-cap{k="ctrl+c"} cancels.

## Revise with AI

:key-cap{k="r"} opens a conversation about one item. The same panel revises a ground-rules answer or a vision answer.

### Writing the request

| Key | Action |
| --- | --- |
| :key-cap{k="enter"} | Send. With nothing typed and nothing proposed yet: keep the text as it is |
| :key-cap{k="alt+enter"}, :key-cap{k="shift+enter"}, :key-cap{k="ctrl+j"} | New line, where the terminal reports these. A line ending in `\` followed by :key-cap{k="enter"} works in every terminal |
| :key-cap{k="pgup"} :key-cap{k="pgdn"} | Scroll the text being revised |
| :key-cap{k="ctrl+v"} | Paste |
| :key-cap{k="ctrl+c"} | Cancel. After a proposal: back to it |

While the agent works, :key-cap{k="ctrl+c"} cancels and leaves the file untouched.

### Reading the proposal

| Key | Action |
| --- | --- |
| :key-cap{k="a"}, :key-cap{k="enter"} | Accept: write it into the file |
| :key-cap{k="r"}, :key-cap{k="e"}, :key-cap{k="i"} | Ask for more changes |
| :key-cap{k="q"}, :key-cap{k="d"}, :key-cap{k="ctrl+c"} | Discard it. The file is unchanged |
| :key-cap{k="y"} | Copy the revised text |
| :key-cap{k="↑"} :key-cap{k="↓"}, :key-cap{k="j"} :key-cap{k="k"}, :key-cap{k="space"}, :key-cap{k="pgup"} :key-cap{k="pgdn"} | Scroll the diff |

### After an error

| Key | Action |
| --- | --- |
| :key-cap{k="enter"} | Try again |
| :key-cap{k="r"} | Edit the request |
| :key-cap{k="ctrl+c"} | Back |

## Reading a document

A proposal, design, tasks or implementation diff opens on its own screen. Its buttons depend on what the document waits for.

| Key | Action |
| --- | --- |
| :key-cap{k="↑"} :key-cap{k="↓"}, :key-cap{k="k"} :key-cap{k="j"} | Scroll a line. The mouse wheel works too |
| :key-cap{k="space"}, :key-cap{k="pgdn"} / :key-cap{k="pgup"} | Scroll a page |
| :key-cap{k="g"} / :key-cap{k="G"} | Jump to the top / the end |
| :key-cap{k="←"} :key-cap{k="→"}, :key-cap{k="tab"} | Choose a button |
| :key-cap{k="enter"} | Press the highlighted button |
| :key-cap{k="a"} | Accept it, or move on to the next step |
| :key-cap{k="r"}, :key-cap{k="ctrl+r"}, :key-cap{k="f"} | Redraft it with feedback: the agent revises it with what you type |
| :key-cap{k="ctrl+e"}, :key-cap{k="E"} | Edit it in `$EDITOR`. Not offered for the implementation diff |
| :key-cap{k="y"} | Copy the document |
| :key-cap{k="q"}, :key-cap{k="ctrl+c"} | Back |

While you type feedback, :key-cap{k="enter"} sends it and :key-cap{k="ctrl+c"} cancels.

### A draft that stopped

When an agent stops instead of writing an artifact, its report opens on the same kind of screen, with these buttons.

| Key | Action |
| --- | --- |
| :key-cap{k="s"} | Revise the requirements it names, in the review |
| :key-cap{k="b"} | Fix the artifact it was drafted against. Asks for your answer, which may be empty |
| :key-cap{k="w"} | Draft it again. Asks what it should go with; empty tries again as it is |
| :key-cap{k="ctrl+e"} | Write it yourself |
| :key-cap{k="q"} | Back |

## Ground rules

The ground rules ask one question at a time, with options. Typing writes your own answer.

| Key | Action |
| --- | --- |
| :key-cap{k="↑"} :key-cap{k="↓"} | Choose an option: ⇐ derived, ★ recommended, Skip, or your own |
| :key-cap{k="enter"} | Pick the highlighted option, save what you typed, or keep the current answer |
| :key-cap{k="tab"} | Skip the question: left for later, never blocking a change |
| :key-cap{k="←"} :key-cap{k="→"} | Move between questions. Once you type, they move the cursor |
| :key-cap{k="?"} | Not sure: an explanation, examples and simpler questions. Only on an empty answer |
| :key-cap{k="ctrl+r"} | Revise the highlighted option, the current answer or your draft with AI |
| :key-cap{k="ctrl+e"} | Open the question's file in `$EDITOR` |
| :key-cap{k="ctrl+d"} | Drop a question the advisor added that is not relevant |
| :key-cap{k="ctrl+f"} | Done: leave the open questions for later and move on |
| :key-cap{k="ctrl+c"} | Back |

Typing "skip", "help" or "not sure", or "done" does the same as :key-cap{k="tab"}, :key-cap{k="?"} and :key-cap{k="ctrl+f"}. While an answer waits on the advisor, :key-cap{k="enter"} or :key-cap{k="tab"} continues without waiting.

## Vision

A new project starts by describing what you are building.

### Describing it

| Key | Action |
| --- | --- |
| :key-cap{k="enter"} | Continue |
| :key-cap{k="ctrl+n"} | Not a new project: go on without a vision |
| :key-cap{k="ctrl+c"} | Back |

### The interview

| Key | Action |
| --- | --- |
| :key-cap{k="↑"} :key-cap{k="↓"} | Choose an option |
| :key-cap{k="enter"} | Answer |
| :key-cap{k="tab"} | Skip the question |
| :key-cap{k="ctrl+r"} | Revise the highlighted option or your draft with AI |
| :key-cap{k="ctrl+d"} | That's enough: make the slices |
| :key-cap{k="ctrl+c"} | Back |

Typing "done" or "skip" works too. When a request failed, :key-cap{k="enter"} asks again.

### Reshaping the slices

| Key | Action |
| --- | --- |
| :key-cap{k="↑"} :key-cap{k="↓"}, :key-cap{k="k"} :key-cap{k="j"} | Select a slice |
| :key-cap{k="space"}, :key-cap{k="x"} | Keep or drop it |
| :key-cap{k="m"} | Merge it with the next slice |
| :key-cap{k="shift+↑"} :key-cap{k="shift+↓"} | Move it. Never before a slice it builds on |
| :key-cap{k="e"} | Reword it: `Title — what it does` on one line. :key-cap{k="enter"} saves, :key-cap{k="esc"} leaves it as it was |
| :key-cap{k="enter"} | Create the roadmap |
| :key-cap{k="ctrl+c"} | Back |

## Jobs pane

:key-cap{k="ctrl+j"} opens the background jobs from the overview, or during a review without losing your place.

| Key | Action |
| --- | --- |
| :key-cap{k="j"} :key-cap{k="k"}, :key-cap{k="↓"} :key-cap{k="↑"} | Select a job and show its log |
| :key-cap{k="x"} | Cancel the selected running job. Asks first: :key-cap{k="y"} confirms, any other key keeps it running |
| :key-cap{k="q"}, :key-cap{k="ctrl+c"} | Close |

## Typing

Every text input edits the same way.

| Key | Action |
| --- | --- |
| :key-cap{k="←"} :key-cap{k="→"} | Move the cursor a character |
| :key-cap{k="ctrl+←"} :key-cap{k="ctrl+→"}, :key-cap{k="alt+←"} :key-cap{k="alt+→"} | Move the cursor a word |
| :key-cap{k="home"}, :key-cap{k="ctrl+a"} / :key-cap{k="end"} | Start / end of the line |
| :key-cap{k="backspace"} / :key-cap{k="delete"} | Delete before / after the cursor |
| :key-cap{k="ctrl+u"} | Delete to the start of the line |
| :key-cap{k="ctrl+k"} | Delete to the end of the line |
| :key-cap{k="ctrl+w"} | Delete the word before the cursor |

Keys cannot be remapped.
