spec-tacular has no settings file of its own. You choose the agent with `--driver`, tune it with environment variables, and describe the project in files under `spec-tacular/`.

## Drivers

`--driver` picks the agent that drafts artifacts, implements, and answers in the TUI: the advisor, the vision interview, change naming and revising a requirement.

| Driver | Agent | How it runs |
| --- | --- | --- |
| `claude` (default) | Claude Code | `claude -p` with stream-json, one process per kind of request, kept open while you answer |
| `opencode` | opencode | One headless `opencode serve` on a local port with its own password, a conversation per kind of request, using its read-only `plan` agent |

```bash
spec-tacular --driver opencode
```

Run `openspec init` for the same agent first: spec-tacular checks that OpenSpec was set up for the driver you chose. The sessions are stopped when spec-tacular exits, :key-cap{k="ctrl+c"} and SIGTERM included.

## Models

By default every request runs on the agent's own model, the one you chose in Claude Code or opencode.

| Variable | Driver | Used for |
| --- | --- | --- |
| `SPECTACULAR_ADVISOR_MODEL` | claude | The advisor, the vision interview and revising |
| `SPECTACULAR_QUICK_MODEL` | claude | Naming changes |
| `SPECTACULAR_OPENCODE_MODEL` | opencode | Everything, as `provider/model`, e.g. `openrouter/anthropic/claude-sonnet-4` |
| `SPECTACULAR_OPENCODE_QUICK_MODEL` | opencode | Naming. Default: `SPECTACULAR_OPENCODE_MODEL` |

Extended thinking is off for these requests: measured on one follow-up, it took most of the time for options of the same quality. `SPECTACULAR_ADVISOR_THINKING=1` turns it back on. Web search is used only when a request touches the stack or tooling.

## MCP servers

::warning
With the Claude Code driver, the agents load your Claude Code MCP servers by default. Headless, nobody can approve a tool call, so spec-tacular approves every MCP tool call itself. The agents may call those tools unattended.
::

| Variable | Effect |
| --- | --- |
| `SPECTACULAR_NO_MCP=1` | Start no MCP servers. Sessions also start faster |
| `SPECTACULAR_MCP_DENY` | MCP servers the agents may not call, matched by name, space or comma separated |

```bash
SPECTACULAR_MCP_DENY="godaddy google_drive" spec-tacular
```

Only MCP tools are approved this way. Built-in tools keep the limits each request sets.

## Permissions

The agents that draft artifacts run headless as `claude -p` with `--permission-mode acceptEdits` and read-only `openspec` commands allowed. Without that, every write would be denied, because nobody is there to approve it.

Implementing runs in your agent's own interactive session, in your own permission mode: auto, accept edits, or ask. spec-tacular only widens it. These never ask:

- the project's test commands, from `verification.yaml`
- the typechecker and linter: `tsc`, `biome`, `eslint`, `prettier`, also through `bunx`, `npx` or `./node_modules/.bin/`
- spec-tacular's own checks: `spec-tacular matrix`, `harness`, `evidence`, `glossary`
- OpenSpec's read-only commands and the commands output is read through, such as `grep` and `head`

To allow more, add Claude Code flags with `SPECTACULAR_CLAUDE_ARGS`. They are split on whitespace and added to drafting jobs and implementing sessions.

```bash
SPECTACULAR_CLAUDE_ARGS='--allowedTools Bash(bun test:*)' spec-tacular
```

## Environment variables

Every `SPECTACULAR_` variable the source reads.

| Variable | Default | Meaning |
| --- | --- | --- |
| `SPECTACULAR_NO_ADVISOR` | unset | Set to any value: no AI during setup, the interview, naming or revising a requirement. Also skips priming the sessions |
| `SPECTACULAR_ADVISOR_MODEL` | Claude Code's model | Claude model for the advisor, interview and revising |
| `SPECTACULAR_QUICK_MODEL` | Claude Code's model | Claude model for naming changes |
| `SPECTACULAR_ADVISOR_THINKING` | unset | Set to any value: let Claude use extended thinking again (slower) |
| `SPECTACULAR_OPENCODE_MODEL` | opencode's model | opencode model, `provider/model` |
| `SPECTACULAR_OPENCODE_QUICK_MODEL` | `SPECTACULAR_OPENCODE_MODEL` | opencode model for naming |
| `SPECTACULAR_NO_MCP` | unset | Set to any value: start no MCP servers |
| `SPECTACULAR_MCP_DENY` | empty | MCP servers the agents may not call |
| `SPECTACULAR_CLAUDE_ARGS` | empty | Extra flags for `claude` in drafting jobs and implementing sessions |
| `SPECTACULAR_FRET_CLI` | `fret.cli` in `verification.yaml` | The FRET command before `formalize`. Takes precedence over `fret.cli` |
| `SPECTACULAR_DEBUG_LOG` | unset | A file path: append each advisor request's session, delta or full, and time, and each priming turn |
| `SPECTACULAR_VERSION` | latest release | For `install.sh`: the release tag to install, e.g. `v0.1.0` |
| `SPECTACULAR_INSTALL_DIR` | `~/.local/bin` | For `install.sh`: where the binary goes |

spec-tacular sets `SPECTACULAR_EXIT_FILE` itself for each background job, to record its exit code. You do not set it.

## Editor

:key-cap{k="ctrl+e"} opens `$VISUAL`, else `$EDITOR`, else the first of `nano`, `vim` or `vi` on your `PATH`. Without any, it says `No $EDITOR set, and no nano or vim found`.

## verification.yaml

`spec-tacular/verification.yaml` tells spec-tacular how to run your tests. `init` writes a starter with every line commented out; evidence is neither collected nor required until you uncomment one.

| Key | Default | Meaning |
| --- | --- | --- |
| `command` | none | Runs your tests and writes a JUnit report |
| `report` | none | Where that JUnit XML report is |
| `matrix.verify` | `auto` | When formal forms are verified through matrices: `auto` (P0 and P1 only), `always` or `never` |
| `matrix.run` | `bun test {tests}` | Runs the given matrix test files |
| `matrix.coverage` | `bun test --coverage --coverage-reporter=lcov --coverage-dir=.spec-tacular/coverage {tests}` | The same, with an lcov coverage report |
| `matrix.lcov` | `.spec-tacular/coverage/lcov.info` | Where that report is |
| `matrix.mutants` | `32` | Mutants per harness check, shared over the files run |
| `matrix.mutation_threshold` | `1` | The share of mutants the matrix must catch, 0 to 1 |
| `matrix.exclude` | `[]` | Files and folders never mutated |
| `matrix.runner` | `test/support/spec-tacular-matrix.ts` | Where the runner is copied |
| `matrix.tests` | `test/matrix` | Where the generated tests go |
| `matrix.harness` | `test/support/harness` | Where the harnesses are |
| `matrix.test_import` | `bun:test` | The module the generated tests import `test` from |
| `fret.cli` | none | The FRET command before `formalize` |

`command` and `report` go together: one without the other is reported as a problem.

## Usage log

The usage sidebar shows the driver, model, cost and the running step. It appears from the start screen on, once the terminal is at least 130 columns wide. :key-cap{k="ctrl+b"} opens the per-model and per-job breakdown at any width.

Cost and tokens come from the agents: Claude reports actual USD, opencode its own cost. The total is kept in `.spec-tacular/usage.jsonl`, so a restart does not reset it. An implementing session reports no cost; its tokens are read from its transcript and shown as *+ implementing*.

## Clipboard

| Platform | Copy | Paste |
| --- | --- | --- |
| Wayland | `wl-copy` | `wl-paste` |
| X11 | `xclip` or `xsel` | `xclip` or `xsel` |
| macOS | `pbcopy` | `pbpaste` |

Without these tools, or over SSH, where they would reach the remote machine's clipboard, copying goes through the terminal with OSC 52. Most terminals and tmux support it. Pasting then uses the terminal's own paste, :key-cap{k="ctrl+shift+v"}. A line in the corner says what was copied, or why not.
